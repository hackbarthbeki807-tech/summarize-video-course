# 视频课程总结与交付

## 核心标准

把课程来源整理成可读、可搜索、可追溯的文字知识库。只有当用户能找到、能打开、能看懂实际课程内容，并且清楚下一步要做什么时，才算完成交付；程序跑完、报告生成或文件夹存在都不等于交付完成。

## 什么场景下用它

- 把本地课程视频、字幕或逐字稿整理为逻辑稿、总览、卡片等知识资料。
- 制作 3–5 个视频的小样、模型对比、固定批次试跑或整门课程成果。
- 将文字成果放入 Obsidian 或其他本地知识库。
- 向非技术用户交付结果，尤其是用户问“我看什么”“这个是干什么的”“下一步做什么”时。
- 修复路径错误、阅读入口不清楚、把 `.cmd` 当阅读文件、电脑文件发给手机等交付问题。

纯媒体扫描可以使用专门扫描器；一旦涉及课程内容整理、阅读体验或人工验收，就使用本 Skill。

## 用它要产出什么

### 每课文字成果

按任务粒度将第一项命名为 `00-本课总览.md` 或 `00-课程总览.md`，其余名称固定：

```text
00-本课总览.md / 00-课程总览.md
01-逻辑稿.md
02-时间戳逐字稿.md
03-知识点卡片.md
04-案例与金句.md
05-质量问题清单.md
media_index.json
```

- 总览：用普通话说明讲了什么、为什么重要、核心结论、建议阅读顺序。
- 逻辑稿：按“背景与问题—判断框架—操作步骤—注意事项”或更贴合原课的结构重组；保留可核对时间戳。
- 时间戳逐字稿：保存原始来源记录，不把它当成日常阅读稿。
- 知识点卡片：每张卡片表达一个可独立复用的概念、方法或判断。
- 案例与金句：只收录原课中真实存在且能定位的案例、原话或明确标注的意译。
- 质量问题清单：记录漏写、重复、低置信度、专有名词、时间戳、硬字幕等待人工核对事项；不静默改写。
- 来源索引：只保存必要的相对路径、时长、校验值、对应文字文件及本地处理标记，不泄露绝对源路径。

### 批次辅助报告

可以生成耗时、质量标记和完成状态汇总，但它只是处理报告，不能替代课程总览、逻辑稿和知识点卡片。不得让用户阅读批次汇总来判断课程内容质量。

### 最终交付说明

每次交付必须直接回答：

```text
现在：做到哪一步。
请先看：一个真实存在、可阅读的具体文件，以及为什么先看它。
你要做：最多 1–3 个普通话动作。
请回复：用户可直接复制的一句话，例如“通过，可以继续”或具体问题。
未确认前：明确不会处理哪些视频、不会删除什么、不会扩大什么范围。
设备说明：这个入口适用于电脑还是手机；若不适用，直接说明。
```

## 必须遵守的规矩

### 先把事情说清楚

1. 开工前说明当前阶段、已完成范围、这一步由谁做、预计时间、磁盘和可能的额度/费用。区分本地计算、模型下载和对话平台额度，不含糊地说“免费”或“没额度”。
2. 技术步骤默认由助手完成。不要把安装、命令、路径判断或模型指标甩给用户；只有内容抽查、授权和主观选择需要用户处理。
3. 需要用户决策时先给明确建议，再说明理由，最后只要求一个简单回复。不要要求用户自己理解 RTF、置信度、token、字数等技术指标后做决定。
4. 每个阶段设置人工闸门。只把用户的批准解释为当时明确约定的范围；未批准的剩余视频不得自动处理。

### 交付实际课程内容

5. 默认阅读顺序为：总览 → 逻辑稿 → 知识点卡片；逐字稿和质量清单只在核对时打开。
6. 用户问“我看什么”时，直接给一篇具体的 `.md`、`.html`、`.pdf` 或其他可阅读文件。不得给 `.cmd`、程序、文件夹或批次运行入口冒充阅读材料。
7. `.cmd` 只能标注为“电脑端启动/打开文件夹的工具”，不能称为总结、报告或文章。
8. 发出路径前必须现场验证文件真实存在、非空、名称准确、内容可读。不得根据计划或预期结构拼接一个未经验证的路径。
9. 只给一个明确的“请先看”入口；若还需抽查其他文件，再按顺序列出。不要让用户在多个时间戳目录里寻找最终版本。
10. 报告成功、测试通过和文件数量正确只是后台验收。用户找不到、打不开、看不懂或不知道下一步时，交付仍然失败。

### 适配用户设备

11. 交付前确认或依据用户刚刚提供的信息判断其使用电脑还是手机。本地 Windows 路径和 `.cmd` 只适用于存放文件的电脑，不能当作手机阅读链接。
12. 用户在手机端时，直接说明本地文件无法由手机打开，并询问其授权的传递方式。不得擅自上传课程内容，也不得把课程全文粘贴到远程对话中。
13. 路径中出现 `BaiduSyncdisk`、OneDrive 等名称，只代表本地目录名称，不代表文件已同步、手机能访问或用户授权使用该云服务。

### 保持本地、只读和可追溯

14. 默认全程本地处理，不把视频、音频、字幕、逐字稿、整理稿或提示词发送给远程模型、付费 API 或云端服务。
15. 源视频保持只读，不复制、移动、重命名或删除。临时媒体只能进入项目规定的 `work/`，最终输出不得保留音视频或转码文件。
16. 正式处理时保留来源相对路径、时长、SHA-256 和时间戳，验证源文件大小、修改时间或校验值未变化。
17. 成品只发布到稳定、清楚的最终阅读目录；中断稿、临时稿和模型原始输出不得冒充完整成品，重复运行不得覆盖已经批准的成果。

### 以普通话交付

18. 先讲结论和用户动作，再讲技术细节。把“RTF 1.06”翻译为“处理 10 分钟视频约需 11 分钟”；技术指标可放在后面供追溯。
19. 明确区分“处理报告”和“课程内容”。用户日常阅读的是总览、逻辑稿和卡片，不是模型对比、批次统计或质量指标。
20. 遇到用户已纠正过的交付问题，先修正固定规则和项目状态，再继续下一步，避免换阶段后重复犯错。

## 执行流程

1. 读取项目规则、状态和实际文件，确认已完成范围、未批准范围与用户当前设备。
2. 小样优先。批量前先估算时长、磁盘、联网下载和费用/额度，并取得明确批准。
3. 从字幕或逐字稿提取事实，生成每课七项文字成果；不要依赖范例补写新课程内容。
4. 验证时间戳单调且未超视频时长、文件非空、结构完整、来源可追溯、输出无音视频和绝对源路径。
5. 现场验证最终阅读文件和路径，按固定交付说明告诉用户先看哪一篇。
6. 停在约定闸门，等待用户回复；没有新授权就不扩大批次。

## 范例

开始撰写逻辑稿前，如果仓库中提供了本地参考范例，读取 [通用逻辑稿结构范例](references/approved-example-template.md)。只模仿它的可读结构、时间戳引用和表达密度，不复用其中的事实、案例、结论或数据。真实课程范例应保存在私有项目中，不要上传到公开仓库。

## 边界

- 不许编造课程事实、数字、时间戳、案例、金句、专有名词、因果关系、讲师观点或处理结果。
- 不确定是原话时标注“意译”；无法从来源确认时写入质量问题清单，不得包装成确定结论。
- 来源缺失、字幕不清、硬字幕未知或时间戳异常时，明确标记“待人工核对”。不要为了文章顺滑擅自补全。
- 拿不准用户意图、批次范围、设备交付方式、云端权限、删除操作或内容判断时，先问用户；未得到回答前保持现状。
- 不得把范例当作模板答案。新课程的结构可以相似，全部内容必须来自新课程来源。
- 不得把“没有自动质量标记”等同于内容完全正确，也不得声称用户已经验收其未明确看过的文件。
- 不得自动删除源视频、扩大到未批准视频、生成整门课程结论、上传网盘、调用远程模型或付费服务。
- 如果本地处理与手机阅读需求冲突，先说明冲突并请求用户选择授权方案，不擅自用任何云盘解决。
