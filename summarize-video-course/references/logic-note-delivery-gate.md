# 逻辑稿可读性与复发故障闸门

在批量生成、修复、发布或验收 `01-逻辑稿.md` 时读取本文件。目的不是让 Markdown “看上去有结构”，而是让用户只看逻辑稿就能说出本课讲什么、按什么顺序讲、有什么可用方法。

## 一、发布前的人读检查

逐篇打开逻辑稿，检查：

1. 开头有 3–8 条完整的“本课学会什么”，每条能独立理解并有来源时间戳。
2. `本课结构` 之后有至少两个具名内容块；标题是完整的主题名，禁止孤立编号标题（如 `### 1`）、`### 知识点：……`、单个词或被截断的长句。
3. 每个内容块至少说明一个完整判断、方法、步骤、场景或例子；禁止“标题 + 同一句复述”。
4. 不得出现截断残留：半个时间戳、未闭合引号/括号、明显未完成句、以省略残片结束的标题或正文。
5. 结构和正文须符合本课笔记类型：框架课拆模型与场景，推导课保留问题到结论，清单课逐项说明类型/公式/用法；不能只把学习要点复制进正文。
6. **长课必须检查覆盖代表性。** 如果逐字稿超过 45 分钟，或覆盖清单跨越多个明显主题，逻辑稿不能只写 2–3 个局部片段。它至少应覆盖课程前段、中段、后段的主要知识主线，并能解释大部分正式卡片如何归入这些主线；课程通知和名单不用于凑覆盖。
7. **术语修正必须可追溯。** 英文缩写或术语被 ASR 按读音写成汉字时，只有后续解释或课件能确认含义，才在阅读层规范为正确术语；原逐字稿保持不变，质量清单记录修正依据。无法确认的专名降级为“专名听写不清”，不得猜名。

任一项失败：课时状态为“知识整理待修复”，不得发布、不得计入批次完成、不得请求人工验收。结构验证通过但现场阅读发现覆盖过窄、明显术语错误或通知内容被当作知识时，同样按失败处理，不能用自动测试结果覆盖人读结论。

## 二、首课复发故障处理

下列任一情况都属于“同类模型故障”：缺少“本课学会什么”、结构标题截断、正文截断、卡片必填字段缺失、案例页被错误写成“本课未发现”。

1. 停止继续下一课；保留转写和模型原始结果。
2. 仅用当前首课的真实逐字稿，在 `work/` 做兼容修复样本。
3. 检查样本的七项文件、逻辑稿人读检查、来源时间戳、输出无媒体和源文件指纹。
4. 修复样本通过后，才允许恢复本批其余课；失败则明确写“批次暂停，正在修工具”。
5. 不把这种修复交给用户确认；用户只验收本批完成后的真实课程资料。

## 三、结束与交付

批次只有同时满足下列条件才可称“完成”：

- 批处理进程已退出，状态文件为 `complete`；
- 预期课时全部完成，课程数量和七项结构通过独立验证；
- 选中的逻辑稿已按本文件现场读过；
- 选中课的七项文件已逐项验证，最终路径适合用户当前设备；
- 修订后的正式课时、批次记录、断点状态包哈希一致；
- 已在同一条完成/验收消息中交付七项真实文件。

在完成上述条件前，统一使用“正在处理/正在修复/尚未到验收阶段”；绝不使用“完成、停止、下一步验收”这类容易误解的词。
