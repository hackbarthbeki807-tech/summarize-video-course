# 案例与金句标准 v3.9

生成、修复或验收 `04-案例与金句.md` 时读取本文件。

## 案例不是摘录

案例及公式后的示例必须同时执行 [具体例子标准](concrete-example-standard.md)，不因字段齐全或故事流畅而跳过来源关与理解关。

先扫描逐字稿中的“比如、例如、举例、假设、场景、我有个客户”等信号及其前后上下文。案例必须由模型在不增加事实的前提下整理成能独立读懂的完整情境，逐字稿残句只能放在“来源摘录/证据”，不能直接当背景、动作或结论。

课程案例与公式后的例子只收录老师在来源中实际举过的内容；“假设案例”指老师本人在课上设定的假设，不是 AI 自编故事。用户要求详细或可理解时，应展开原例上下文与概念对应，不能另造一个更完整的事件来替换。原课只给回答骨架时，按骨架说明；缺失的动作、数字、结局保留缺失，不能把填空项写成已经发生。

最低结构：

1. **案例类型**：真实案例 / 行业案例 / 课堂示例 / 正反例 / 假设案例。
2. **背景**：主体或产品是谁，原来的做法或现状是什么，什么问题触发了后续动作。
3. **问题与分析**：遇到了什么具体问题，为什么原做法不能解决。
4. **动作/改造方式**：具体做了什么，不能只写“进行了优化”。
5. **结果**：来源明确说明的结果；没有数据或结果时写“来源未说明”，不编造。
6. **可复用启发**：读者可以迁移的判断、步骤或注意事项。
7. **来源时间戳**：保留可核对时间戳。
8. **来源摘录/证据**：必要时附短摘录，并标明意译或待核对。

如果来源同时包含目标、执行动作、数据、转折、失败和调整，扩展为：背景 → 目标与初始问题 → 执行动作 → 数据结果 → 关键转折点与调整 → 失败/限制 → 可复用经验 → 来源。

只有逐字稿确实没有可独立复述的情境时，才能写“本课未发现”。模型保守、转写残缺或没有主动扫描举例信号，都不是直接写“未发现”的理由。

## 金句标准

金句至少满足：完整句、离开上下文仍能理解、表达了可复用判断或方法、来源可追溯。区分：

- **老师原话**：只有能逐字确认时使用。
- **原话候选（待音频核对）**：转写可能有错字但值得复核。
- **模型整理/意译**：不得用引号冒充老师原话。

### 可复用表达强制扫描

生成 `04-案例与金句.md` 时，必须在写“本课未发现”前扫描逐字稿中的：完整判断句、定义句、公式/步骤、通知或沟通模板、行动建议、总结口诀，以及“先……再……”“问题→方案→结果”等结构表达。满足“完整、脱离上下文可理解、可迁移、可追溯”四项的内容必须提取；如果课程存在 A+B+C、步骤链、条件分支或顺序关系，必须优先写成“公式/结构”，再附原话或案例作为例子，而不是只摘抄句子。每条还要写明适用场景、内容性质和来源时间戳。仅有口头填充词、半句残片或无法独立理解的句子才可排除；转写疑似错词应在整理层标注待核对，不得因此跳过候选表达。

口头填充词、残句、普通定义、没有上下文的半句话不是金句。没有合格表达时如实写“本课未发现”，不自创口号。

### 生成结果的最低记录

每次扫描都要在 `04-案例与金句.md` 留下 `## 可复用表达`，并在 `media_index.json` 的 `reusable_expression_review` 留下结果：

- `status`：有合格表达时为 `extracted`；确认没有合格表达时为 `reviewed_no_eligible_expression`；扫描未完成不得发布。
- `candidate_count` / `published_count`：候选数量和实际写入数量，不能用“0”掩盖未扫描。
- `formula_first`：存在公式、步骤、分支或顺序关系时为 `true`。
- `scan_signals`：记录命中的表达信号，如“公式/步骤”“沟通模板”“总结判断”“案例启发”。

复用表达的推荐呈现顺序为：

```text
名称 → 公式/结构（A+B+C、步骤或条件分支）→ 适用场景 → 使用方式 → 内容性质 → 来源时间戳 → 示例/限制
```

如果表达只来自模型归纳，必须写“模型整理/意译”；只有逐字可核对的短句才标“老师原话”。
