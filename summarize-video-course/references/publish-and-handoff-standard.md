# 发布硬校验与交接标准（公共版）

正式发布前必须核对批次清单格式、精确课时 ID 集合、候选七项、来源标记、课件原件与索引，以及自动格式检查和独立语义复核。暂存包通过不等于正式发布；来源缺号记为 `source_gap`，不得推断课程原本没有该课。

当全批候选均已复核而正式发布数未增加时，立即执行发布接续自检，不等心跳超时：

1. 钉定证据快照版本、清单哈希、逐字稿哈希和已复核课时集合；对照正式目录已发布的精确集合。
2. 阅读实际发布器，列出它会重建的课程首页、课件索引、来源索引和状态文件；对照旧课件与新增课件的精确集合及 SHA-256。可能覆盖手工内容或漏复制新课件时不得直接运行。
3. 只在 `work/` 做 `stage-only` 彩排，验证七项、旧资料保留、新课件就位、链接可打开、无音视频与源绝对路径；失败时正式目录保持不变。
4. 在授权范围内使用单写者锁、完整备份和可回滚提交；失败保留原因和断点，不把部分发布写成完成。
5. 发布后从正式路径重开逻辑稿、该课七项、课程首页、课件索引与必要原件；复核课时集合、指纹、链接和进度页。全部通过才进入人工验收。

送外部审查前须准备冻结包：课件融合记录、知识覆盖表、修复日志、同类问题回扫、七项文件哈希及包指纹、只读闸门结果。冻结后不原位改包；修改须重新冻结。自动检查通过只证明可机械判定的格式和结构，不代表事实或语义正确。
