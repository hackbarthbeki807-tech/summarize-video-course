# 交付前 AI 质量委员会与根因修复标准 v1.1

## 目的

课程交到用户前，AI 团队必须先把“只摘抄逐字稿、漏掉画面知识、漏掉 A+B+C 公式、案例背景空泛、卡片覆盖不足”等基础问题查出来并修好。用户只抽查高风险和边界项，不承担基础质检。

## 固定检查顺序

1. **知识覆盖审计**：建立“时间段—知识点—方法/公式—例子—来源”清单，逐项核对总览、逻辑稿和卡片；重复标题、无时间戳、只写摘要均失败。
2. **复用表达审计**：优先扫描 `A+B+C`、步骤链、条件分支、模板、沟通句式和总结口诀。只要逐字稿出现信号，就必须输出“公式/结构 → 例子 → 适用场景 → 来源时间戳”；占位语不能通过。
3. **案例审计**：案例必须能脱离逐字稿复述，至少交代主体/产品、原来的做法或现状、触发问题、分析、动作、结果（没有来源就写“来源未说明”）、可复用启发和时间戳。`课堂以……为例` 等提示语不能充当背景。
4. **画面知识审计**：每个视频必须有画面筛选结论。方法、分类、流程、图表、漏斗、思维导图等画面必须保留必要原图/页面，并写结构化解读；OCR 只能辅助检索，不能把扁平 OCR 冒充视觉理解。结构图语义不确定时阻断交付并记录需人工核对。
5. **结构与来源审计**：七项文件、相对链接、时间戳、来源指纹、无音视频、无绝对源路径全部通过后，才允许进入发布。

## 失败处理

- 首次失败自动进入“修复窗口”：只重写失败的阅读层块，不重转写、不改逐字稿、不覆盖已验证课时。
- 修复后再次运行同一闸门；仍失败则保留断点，状态为 `blocked_requires_repair` 或 `blocked_requires_human_review`，不得把问题交给用户才发现。
- 任何字段拿不到证据都写“来源未说明/待确认”，不能为了通过而补编。

## 历史包回溯责任

- 课程收尾前必须对所有历史正式课时、小样转正式包和恢复包重新运行本闸门；旧版本“已通过”不构成豁免。缺少画面语义、复用公式、完整案例或实际原图的旧包，先复制到 `work/` 暂存修复，不能直接交给用户。
- 修复记录必须包含课时、缺项、来源依据、修改文件、修复前后状态和未解决风险。历史包修复不改 `02-时间戳逐字稿.md`，正式发布须走备份、连锁刷新和全课程终检。
- 画面项除了检查摘要长度和占位词，还必须检查索引相对路径对应的文件真实存在；只有路径字符串而没有原图时仍视为失败。模型不可用时，案例动作可做确定性步骤链回退，但不得用回退生成图表语义或新的课程事实。

## 完成条件

`media_index.json.pre_delivery_quality_gate.status` 必须为 `passed`。未通过的课时不能标记完成、不能发布，也不能作为批次验收入口。
