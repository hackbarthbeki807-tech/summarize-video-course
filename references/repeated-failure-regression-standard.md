# 反复漏项回归标准

本标准把近期实际交付中反复由用户补救的动作，变成生成前、发布前和交付前的固定门禁。它不是“发现问题后再提醒”，而是要求 AI 团队在交给用户前完成证据闭环。

## 一、生成前防漏清单

每个课时建立一份覆盖记录，逐项写明完成、排除或阻断原因：

1. **来源覆盖**：视频、字幕、PDF/PPT/Word、图片和电子书逐文件入清单；不能只处理看起来像正文的文件。每个来源必须有明确去向，课程名、课时号和输出目标必须从授权目录和清单确认。
2. **课时筛选**：导览、前言、平台教程、通知和致谢不硬凑知识点；保留筛选结论和逐字稿，正式知识课单独统计。
3. **画面知识**：根据逐字稿提示和候选帧筛选真正承载知识的画面。凡保留关键画面，必须同时完成：原图可打开、视频时间戳、本地 OCR（辅助文本）、视觉语义总结。表格、流程图、漏斗、思维导图和公式不得只交扁平 OCR；OCR 看不清的字词标“待核对”，图示关系不确定标“需人工核对”。没有知识画面也必须记录排除理由。
4. **复用表达**：完整扫描逐字稿中的公式、步骤、条件分支、模板、话术和总结口诀。发现结构时先写 `A+B+C`/步骤链/分支，再写适用场景、使用方式、例子、内容性质和来源时间戳；不得把空泛“未发现”当作扫描结果。
5. **案例重构**：每个独立案例至少写清主体/产品、原状和触发问题、问题分析、具体动作、结果、限制和可复用启发；行业/运营复盘还要补目标、初始问题、关键转折和数据口径。逐字稿残句只能放在来源摘录，不能冒充背景或动作。
6. **术语校正**：阅读层发现明确 ASR 错词时，依据画面文字、上下文或老师后续说法修正 `00/01/03/04/05`；`02-时间戳逐字稿.md` 永不改写。无法确认的词保留原样并标重点核对。

## 二、发布前回归门禁

- `media_index.json` 必须同时有 `reusable_expression_review` 与 `visual_review`；画面记录必须含 `ocr_text` 或明确 `ocr_status`，以及非占位的 `knowledge_summary`。
- `04-案例与金句.md` 必须能找到扫描结果、公式/结构和完整案例；出现“本课未发现”时必须附扫描范围与排除理由。
- `00-本课总览.md`、`01-逻辑稿.md`、`03-知识点卡片.md` 中涉及画面知识时，必须给相对图片路径和时间戳；不能只在 `05-质量问题清单.md` 里报告“以后补”。
- 逐课七项资料必须位于 `outputs/<课程名>/课时资料/<课时>/`，不能误发布到课程根目录、批次目录或只留在 `work/`。
- 批次清单与正式输出做精确集合比对：不得漏课、错课、重复课时；每课源指纹不变。
- 进度百分比只统计完整验证课时；`100%` 仍需继续发布验证和用户验收。失败必须同步到批次状态和同一实时进度入口，不能留下旧百分比假装未发生。

## 三、交付前 AI 团队责任

用户只承担高风险例外的阅读判断，不承担基础找漏。交付前按以下顺序执行并留下证据：

`覆盖清单 → 画面 OCR/语义 → 复用公式 → 完整案例 → 术语校正 → 七项验证 → 实际打开 → 单一进度链接交付`

任一环节失败时：

1. 只修复失败课时，不重做已验证转写；
2. 先在 `work/` 备份并修复，再重跑质量闸门；
3. 仍失败则明确写入失败原因和可恢复断点，禁止发布残缺稿；
4. 同一里程碑只通知一次，普通心跳只刷新进度文件，不刷屏；
5. 只有实际打开的逻辑稿和七项文件交付后，才进入人工验收。

## 四、交付后抽查

每次用户指出一个漏项，必须做两件事：

- 修正当前课时的正式文件、暂存副本、媒体索引和质量清单；
- 在本 Skill 的回归记录中新增对应失败模式和自动检查条件，避免只修当前文件而不修流程。

## 五、第 3 批首审暴露的重复失败模式（2026-09-24 生效）

Codex 对 14/15/17/18/19 五课首审共 5 条 critical、31 条 major、13 条 minor；其中**同一类严重错误出现在 4 节**（把反例写成许可、把判断方向反转）。按协作方案 V2.0.0 第四节，已触发"暂停送审 → 先修生产模板 → 回扫同批 → 再恢复队列"。

以下六条定为生成后、送审前的强制自查项，逐项留证据：

1. **事实方向反转**：把反例写成许可或建议、把带条件写成无条件、把"对象 A 承担损失"写成"对象 B 承担损失"。
   强制：每条带判断方向的结论，回逐字稿**复读原句**并记录原句与时间戳；否定词（不／并非／除非）、行动主体、适用条件、结果四项逐字比对。
2. **角色错置**：把弱势方动作归给强势方、把"我进他退"的话术套到"他进我退"。
   强制：涉及两类角色的知识分别成卡，各写适用条件与话术，不合并成泛化步骤卡。
3. **案例串人与编造结局**：多个主体揉进一个案例；把一般建议写成某人的真实后续；把学员留言升级为讲师结论。
   强制：一主体一案例；**实际发生／讲师建议／学员留言**三栏分离；来源未说的写"来源未说明"，不补结局、动机、数据。
4. **时间与内容错配**：用机械分窗的窗口边界代替真实内容定位，导致证据回查落空。
   强制：逐块按内容重定位，跨段知识写多个准确区间；卡片顺序贴合授课顺序。
5. **占位与伪知识**：卡片定义写"本课未说明可独立复述的定义"、用"第一项／第二项"当公式、把生产分类标签当课程知识、全部卡片标"重点核对"。
   强制：**先建覆盖表再写卡片**；标题必须是具体知识名；重点核对只给确有歧义、专名、逐字引语或强断言者，其余标"常规阅读"。
6. **把自动闸门 passed 当成语义通过**。
   强制：脚本通过只记 `format_passed`；语义结论必须由**与写稿分离的检查上下文**出具，并在 `05-质量问题清单.md` 写明这一区分。

7. **清洁改写时改变事实强度**：为删掉交付稿里的内部返修自述而重写句子时，顺手把「本人猜测／来源未说明因果」升级成确定因果，或把条件判断写成绝对结论（第 14 节 r5 的 major 即由此产生）。
   强制：清洁动作**只删自述、不重写事实**；确需重写的句子，必须回逐字稿复读原句，核对事实强度词（猜测／推测／可能／来源未说明 —— 对 —— 就是／正是／导致）与时间戳，并复查同包案例页、质量清单的口径是否仍一致。机械兜底见 `semantic_regression_check.py` 的 C8。

**回扫要求**：同一类严重错误在 ≥2 节出现时，暂停继续送审；修完提示与检查模板后，回扫同批全部已生成包，回扫报告逐节记录该类错误是否已消除、证据在第几行，再恢复队列。回扫不通过的包不得进入 `ready_for_external_review`。

### 具体例子的可理解性回归（2026-10-09 补充）

曾把“应问什么、应交代什么”以及规则、例外的摘要写进“具体例子”；修复时又错误地把“要详细、要看懂”当成允许 AI 自编教学故事。执行知识点卡片标准第三节：逐卡回到老师原例的上下文，保留原有事实并解释概念对应。仅有例子字段或教学假设标签不算通过；人物、动作、对白、数据和结果都须有源依据。老师本人只给框架时如实标为框架，不为凑完整而编故事；不同于把已讲完整的原例压成待填框架。任何自创例子须从正式阅读层移除并核对同课逻辑稿、公式示例和案例页，不以标签掩盖内容不合要求。

## 六、工程与交接类重复失败模式（2026-09-24 生效）

第五节管的是**知识内容对错**。本节的六条管的是**机器与流程**，它们同样反复出现，且造成的损失更直接：白跑数小时、发布返工、外审额度被草稿耗光。

1. **长任务进程树被回收**：启动器拉起 worker 后自己退出 → 后台任务判定结束 → 整个进程树被杀，日志却是空的。
   强制：启动脚本末尾 `while worker.poll() is None: sleep(60)` 阻塞到底。详见 [本地运行工程回归标准](references/local-run-engineering-standard.md) 第二节。
2. **代理污染本机请求**：会话注入的 `HTTP_PROXY` 会把 `127.0.0.1:11435` 的请求也转发走，表现为"本地模型挂了"，实为被拦。
   强制：派生 worker 前 pop 全部代理变量并设 `NO_PROXY=*`。
3. **来源配对靠命名推导**：`with_suffix('.pdf')` 遇到文件名尾数差异（第 14 讲音频带 `1`、第 19 讲无前导空格）必然错配。
   强制：显式映射表 + 唯一性断言。
4. **发布硬校验三件套每次都卡**：缺字面「视频：」标记、`media_index.json` 出现 `http://`、正式目录缺本节课件资料。
   强制：发布前逐项确认，见 [发布硬校验与外审交接标准](references/publish-and-handoff-standard.md) 第一节。
5. **把草稿送外审**：课件未融合、覆盖表没有、遗漏回归没做就送出去，审查员只能报一堆"未完成"，白耗额度。
   强制：送审前必须做成冻结包（课件融合 + 覆盖表 + 修复日志 + 同批回扫 + 带哈希的冻结清单），一次只送 1 节，且交接单必须附防误报清单。
6. **把缺号写成"课程本来没有"**：第 16 讲本地缺文件，但第 18 讲课件明写有这一讲，正确记法是 `source_gap`。写错会让整门课完成度统计失真。

以上各条的执行细节、命令形态和已验证的无效做法，分别见 [本地运行工程回归标准](references/local-run-engineering-standard.md) 与 [发布硬校验与外审交接标准](references/publish-and-handoff-standard.md)。**这两份是启动批次和发布前的必读项，不是事后参考。**
