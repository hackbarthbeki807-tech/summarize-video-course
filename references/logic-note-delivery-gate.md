# 逻辑稿可读性与交付闸门（公共版）

在批量生成、修复、发布或验收 `01-逻辑稿.md` 时读取本文件。目标是让用户只看逻辑稿就能说出本课讲什么、按什么顺序讲、有什么可用方法。

## 一、发布前人读检查

逐篇打开逻辑稿，确认：

1. 开头有 3–8 条完整的“本课学会什么”，每条能独立理解并有来源时间戳。
2. “本课结构”之后有至少两个具名内容块；标题是完整主题名，不能是孤立编号、单个词、占位标题或截断句。
3. 每个内容块至少说明一个完整判断、方法、步骤、场景或例子。
4. 不出现半截时间戳、未闭合引号或括号、未完成句、截断标题和明显的模型输出残片。
5. 正文符合课程类型：框架课拆模型与场景，推导课保留问题到结论，清单课逐项说明类型、方法和用法。
6. 正文不能只复制“本课学会什么”，也不能使用“标题 + 同一句复述”冒充内容。

任一项失败，课时状态为“知识整理待修复”，不得发布、计入批次完成或请求人工验收。

## 二、首课复发故障处理

下列任一情况都属于同类模型故障：缺少学习要点、结构标题截断、正文截断、卡片必填字段缺失、案例页错误地写成“本课未发现”。

1. 暂停继续处理下一课，保留原始来源和模型结果。
2. 只用当前首课真实来源，在工作目录制作兼容修复样本。
3. 检查七项文件、逻辑稿人读、时间戳、无媒体和来源指纹。
4. 样本通过后，才恢复本批其余课时；失败时明确写“批次暂停，正在修工具”。
5. 同批技术修复不重复交给用户确认；用户只验收批次完成后的真实资料。

## 三、完成与交付

批次同时满足以下条件才可称为完成：

- 处理进程已退出，状态为 `complete`；
- 预期课时全部完成，数量和七项结构通过独立验证；
- 至少一篇本批逻辑稿已现场打开并通过人读检查；
- 选中课的七项文件均已验证，最终路径适配用户设备；
- 修订后的正式课时、批次记录和断点状态包哈希一致；
- 同一条完成或验收消息已经交付七项真实文件。

在条件全部满足前，统一使用“正在处理”“正在修复”或“尚未到验收阶段”，不要使用容易误解的完成式措辞。
