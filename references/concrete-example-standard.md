# 具体例子：原例忠实与学生可读标准

版本：V3.28.1 ｜ 更新于 2026-10-09

适用于逻辑稿、知识点卡片、案例页、公式后的示例以及课程手册。目标不是凑字数，而是让学生通过课程中的具体情境理解抽象知识、关键特征和适用边界。本标准同时约束证据准备、写稿、独立复核与修订；外部工具提供的候选也须按同一标准回源。

## 一、例子从哪里来

- 只使用老师在课程音频、视频或配套课件中实际举过的例子。AI 自编人物、对白、工作任务、动机、数字和结局，即使标“教学假设”，也不能进入课程例子。
- 老师本人提出的假设、类比、正反示范可以保留，但标明“老师课堂假设／示范”，不写成真实发生的事件。老师转述的新闻或影视情节仍保持转述性质。
- “具体一点、学生看得懂、多举几个例子”不是授权补造事实。先找回原例前后文及课件里的细节；不能从常识或其他课程补完这段故事，也不能把不同主体的经历拼成一个事件。
- 允许重排叙述、解释指代、说明原有关系，但区分“来源事实”和“笔记对概念的解释”。来源只有个人猜测，不能改成确定因果；没给结果，不能补成成功案例。
- 完整扫描后确实没有原例，写明没有完整原例；老师只给回答框架，就保留框架并解释各部分作用，不把留空项填成经历。原文模糊时保留疑点，不能猜测后贴一个时间戳冒充证据。

## 二、怎样写得具体、好懂

先讲清原情境，再解释知识点。根据来源实际提供的内容，交代“谁／什么对象，在什么背景下，遇到什么问题，做了什么，发生什么结果”，并保留关键转折、条件和限制。**这些是检查问题，不是强迫每个例子填满的表格**：关系类例子可能只需人物关系，过程类才需要动作与结果；缺失字段不能补编。

写成自然、连贯的学习笔记，不写“讲师通过某案例阐述某观点”这样的报告摘要；不把“应说明哪些字段”“可以问什么”当成讲完的故事。需要用“老师回忆／老师假设”辨别来源时保留，不必句句第三方转述。

例子后必须让读者看见它与知识的对应：

- 哪个具体细节体现了这个概念，而不只是重新说一遍定义？
- 为什么这个动作或关系重要？同类事物容易混淆在哪里？
- 原例能说明什么，不能说明什么？

优先选课堂中贴近日常经验、关键特征明确的原例。若老师有多个表面不同而结构相同的例子，可并排说明共同结构，帮助迁移；数量由来源决定，不硬凑双例或三例。老师原有的类比、提问和练习可保留；不为满足“多个例子／练习”另造内容。

关系箭头、步骤链或小对照表只用于把原有关系讲清楚，不能新增关系。原课件的表格、流程、结构图确有不可替代的信息时，保留必要原图和解读；装饰背景加一句话只提炼文字，不以多存图片冒充具体。

## 三、写前与交付前自检

写前在现有知识覆盖清单中定位原例及前后文，优先复用已有转写和课件证据。写后由独立于作者的上下文复核，在既有遗漏报告中对每个例子记录以下结果，不另造一套重复报告：

1. **来源关**：标明例子所在文件／卡片、时间戳或页码；逐项核对主体、背景、动作、数字、否定、条件、因果与结果，区分真实经历、老师假设和回答框架。一个宽时间范围或“模型整理”标签不能替代核对。
2. **理解关**：假设老师只照这段给没听过原课的学生讲，学生能否说清“发生了什么／是什么关系、哪处体现知识点、为什么、边界在哪”？审查人须复述关键对应关系并记简短依据，不能只勾“能看懂”。这是 AI 可理解性检查，不是假装有真实学生反馈。
3. **修复关**：不懂就回源找遗漏上下文、调整叙述、解释原有关系；来源不够就如实保留不足。发现自编或仍然空泛，定向修复并复查受影响段，不能只换标签、拉长文字或交给用户找问题。

任何一关未通过，保留暂存，不发布或声称质量通过。自动七项、字数、时间戳和链接校验只证明结构，不能证明例子忠实或读者理解；旧审核不能用于证明改写后的例子通过。

## 四、规则回归检查

升级或修复此类问题时，至少检查以下判定是否仍成立：

| 候选表现 | 应如何处理 |
| --- | --- |
| 只写“老师用某经历说明某概念” | 不通过理解关，回源展开真实细节与概念对应 |
| 故事很清楚，但人物与情节由 AI 新编且标教学假设 | 不通过来源关，移除并换课堂原例 |
| 原例只有汇报关系，笔记解释各人在关系中的角色 | 有据且能独立读懂可通过，不要求补事件结局 |
| 老师自己的假设含数字，但没有实际结果 | 保留原数字与假设身份，不写成真实业绩 |
| 原课只给回答骨架，没有完整案例 | 如实保留框架，不伪造故事，不谎称已提取完整案例 |
| 表面不同的两个老师原例，笔记解释共同结构 | 可用于迁移；不得串写主体、因果或结果 |
