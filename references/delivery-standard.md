# 交付与验收标准 v3.10

任何消息只要包含“请验收、通过后继续、批准下一批”等含义，必须先执行本文件。

## 不可绕过的验收文件闸门

1. 本批预期课时全部发布，批次状态和进程状态均有证据，不以后台启动、断点或目录数量代替完成。
2. 如果消息声称“整门课程完成”，先核对来源覆盖清单的六层状态；课时数量通过但来源、画面、课件融合或人工验收未完成时，只能报告阶段完成。
3. 现场打开本批新发布的一篇 `01-逻辑稿.md`，用 manifest、课时相对来源和该课 `media_index.json` 证明它属于本批。
4. 逐项打开这节课的六个 Markdown，并解析 `media_index.json`；七项必须非空、名称正确、链接真实。
5. 打开将发送给用户的同一个最终链接，确认它适用于用户当前设备。手机不能只给本机 D 盘路径；不能让用户自己从文件夹里找。
6. 同一条消息只设一个“请先看”的优先入口，推荐“总览 → 逻辑稿 → 知识点卡片”，但必须同时列出七项入口和用途。
7. `.cmd`、文件夹、批次报告、状态 JSON 和计划中的路径都不能冒充课程文章。

任何一项不满足，删除验收请求，只能说“尚未到验收阶段”，说明当前状态和下一检查点。

## 完成消息最少包含

- 本批实际完成课时数和课程累计进度。
- 请先看的真实逻辑稿链接。
- 本课完整资料共七项：总览、逻辑稿、逐字稿、知识点卡片、案例与金句、质量清单、来源索引。
- 逐字稿用于核对原话，质量清单用于看风险，`media_index.json` 用于来源追溯。
- 用户只需重点判断能否看懂、知识点是否完整、案例是否可独立理解；不要求逐条核对全文。
- 未经本批验收不启动下一批；课程已经收尾时明确“不存在下一批”。
